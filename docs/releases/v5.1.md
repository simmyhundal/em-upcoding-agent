# v5.1

The agent on data 4.0 (D4.0) and score 4.0 (S4.0), mirroring workflow v4.1 inside its tools. Run once on the ten test seeds (5555 to 6464; the agent line's second use; $1.242 for ten runs, below the $1.7 estimate).

![The flow this version builds on](https://raw.githubusercontent.com/simmyhundal/em-upcoding-agent/main/docs/images/agent.svg)

## What changed
1. **Ask and skip advice for the first 4 listed providers only** (`screen_providers`), so the agent triages only the providers it asks.
2. **The loosened chart rules** (`hybrid_review`), with a `demand_check` for called providers: the point estimate, the 90% lower bound, the cost of a demand and a near-miss flag.
3. **One second random request for a near-miss** (`request_records`; more than 30 charts is refused). The demand floor, the narrow binding rule, the stop-after-first-sample advice and the code repair of the two writing defects stay.

## Headline result
Ten test seeds: **10 of 80 upcoders found, 0 honest providers called, score 4.0 of +$7,426 in all (+$743 per seed)**, against 3 found and −$7,812 for agent v5.0: +$1,524 per seed, better on 7 seeds and worse on 3, one-sided exact p = 0.0078. Against workflow v4.1 it is −$260 per seed (p = 0.53): the agent and the workflow are not distinguishable. Against zero p = 0.15: not distinguishable from zero. One seed (5959, +$5,002) carries the total; without it v5.1 averages about +$270 per seed.

A scripted agent that follows the advice matched the workflow's asks on 20 of 20 development seeds and its calls and extensions on 19 of 20 (docs/agent_v51.md).

## Known limits
- One run per seed, ten seeds, a model that can ignore advice; the agent's triage of only the providers it asks favours it by about $13 per provider.
- The records budget stays 22, so the list of 4 is advice, not a rule.
- Same data and score limits as v4.1.
