# v1.0

The first workflow: statistics screen, an AI writes and filters, code checks citations, people review. Held-out freeze of the version-1 data.

![Statistics screens upcoders then AI suggests and explains. Humans review generated cases.](https://raw.githubusercontent.com/simmyhundal/em-upcoding-agent/main/docs/images/how_it_works_v1.0.svg)

## How it works
1. **Billing data.** Claims data. Here: synthetic claims shaped like public Medicare numbers.
2. **Statistical screen.** Flags doctors who bill the top visit code unusually often for their patients. The most unusual go on.
3. **AI review.** Reads each flagged doctor's evidence and writes a short explanation citing the exact visits.
4. **AI filter.** In the same call, suggests: looks like upcoding, sicker patients, or unclear. Only 'upcoding' moves on.
5. **Citation check.** Code rejects any summary that cites a visit that does not exist or belongs to someone else.
6. **Case pages.** One page per flagged doctor: the summary, its cited visits and a chart against peers.
7. **Recovery packets.** For suspected upcoders only: records to request, a sample plan, an overpayment estimate.
8. **People review.** SIU reviewers read the cases. Payment integrity requests records and decides what happens next.

## Headline result
Held-out run: 8 of 8 upcoders called, 0 of 17 honest doctors accused (charts were handed over, so optimistic).

Numbers are not comparable across versions (different data and inputs). Full table: [docs/results.md](https://github.com/simmyhundal/em-upcoding-agent/blob/main/docs/results.md).

## Known limits
- Synthetic data from one generator; two seeds.
- The AI is handed a records sample before it decides, which a payer would not have.
- Usefulness 3.4 against a target of 4.
