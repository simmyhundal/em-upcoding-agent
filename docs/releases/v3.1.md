# v3.1

The agent on data 2.1: new tools to check notes and request the audit trail, a lint that refuses unsupported findings, and a reason for every screened doctor it sets aside. Evaluated with the workflow on ten fresh seeds (#61).

![The agent and the actions it chooses from: screen, look closer, request charts, follow up, check notes, estimate, review, submit findings.](https://raw.githubusercontent.com/simmyhundal/em-upcoding-agent/main/docs/images/agent.svg)

## What changed from v3.0
1. **Data 2.1 and provider office 2.1.** Notes come with the charts; a second records request and an audit-trail request are allowed.
2. **New tools.** `note_checks` (claim versus note) and `request_audit_trail`.
3. **Findings lint.** `submit_findings` refuses leanings the evidence does not support, figures that do not match, contradictions, and quoting an unreliable estimate; every strongly screened doctor needs a finding or a `set_aside` reason.
4. **Screen table.** Magnitude columns (ratio to expected, excess claims, excess dollars) and `priority` ordering.

## Headline result
Ten fresh seeds (80 planted upcoders): **27 of 80 upcoders found, 0 honest doctors accused** (v3.0: 18 of 80, 0 accused), with 101 request rounds to honest practices (workflow v2.1: 203). Paired by seed, v3.1 finds 0.9 more per seed than v3.0 (+0.1 to +1.8) and 0.5 fewer than workflow v2.1 (-1.2 to +0.2): no confirmed gap, so the workflow stays the main line and the agent stays in development.

Full tables: [docs/eval61.md](https://github.com/simmyhundal/em-upcoding-agent/blob/v3.1/docs/eval61.md).

## Known limits
- Still misses two thirds of upcoders; no arm meets the 12.5% miss-rate threshold.
- Costs more per run than the workflow (about $0.53 against $0.19 per seed).
- Summaries are short on interpretation (LLM judge 3.3, target 4).
- Simulated provider office; synthetic data from one generator family.
