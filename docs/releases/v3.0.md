# v3.0

The agent design: a model chooses its own tools and steps within caps, against a simulated provider office. The v2.0 workflow stays frozen as the comparison.

![An agent chooses the next step. Code limits and checks it. Humans review the findings.](https://raw.githubusercontent.com/simmyhundal/em-upcoding-agent/main/docs/images/how_it_works_v3.0.svg)

## How it works
1. **Claims data.** Plan-shaped synthetic data: members, claim lines, denials. Conditions are derived from the claims.
2. **Screen tool.** A statistical screen the agent can run with any cutoff, as often as it likes.
3. **Agent decides.** A model picks the next step within caps: look closer, compare peers, ask for charts, follow up, stop.
4. **Provider office.** Simulated practices answer: complete, partial, late, unusable or not at all.
5. **Evidence checks.** Chart rule, claim facts and summary rules, available to the agent as tools.
6. **AI findings.** The agent submits a leaning for each doctor it examined, with a short interpretation.
7. **Checks.** A citation check and a number check run on the findings; every tool call is logged.
8. **People review.** Findings are drafts. People decide; nothing is sent automatically.

## Headline result
Same two seeds: 4 of 16 upcoders found, 0 honest accused; 9 honest practices asked for charts.

Numbers are not comparable across versions (different data and inputs). Full table: [docs/results.md](https://github.com/simmyhundal/em-upcoding-agent/blob/main/docs/results.md).

## Known limits
- Found fewer upcoders than the workflow on the reserved seeds (4 of 16 against 6), with fewer honest practices asked.
- Agent summaries score 2.3 to 3.0 on usefulness (target 4).
- Not yet tested below a 3.7% upcoder rate.
- Recovery (extrapolated dollars, post-flag rounds) is not simulated yet.
