# Seed pools: who fitted, selected, confirmed and tested on which seeds

[Back to the README](../README.md) · [versions and seeds](versioning.md)

Generated by `python eval/seed_registry_report.py --write` from `experiments/seed_registry.json` (the source of truth; `src/seed_registry.py` reads it, and `eval/w_loop.py` and the fresh-seed run scripts check it before running). A seed number alone means nothing: data 4.0 seed 1515 and data 2.2 seed 1515 are different datasets, so every pool is keyed by data version and seed list. Free to read; nothing here runs a model.

## Words

- **fit**: parameters of a model are estimated on the seeds.
- **select**: a setting or a design choice is made on the seeds.
- **confirm**: a hold-out read once for a decision declared in advance.
- **test**: a fresh seed set read once for a frozen version.
- **burned**: results were read before a later decision was made; the seeds are development data for everything after.
- **fresh**: never run by anyone.
- **reserved**: held back and never generated; changing this needs a deliberate edit of the registry.
- **in use**: read for declared decisions and still clean for hypotheses whose design did not see those results.

A seed is a hold-out only for one arm and one decision made before its results were read. When a result from a pool informs a later design, the pool is burned for that line. Each new family of hypotheses gets a new confirm pool (making development seeds is free); the final test pool stays untouched until the freeze.
