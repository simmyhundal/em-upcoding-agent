# Agent cost on the stored release 1 runs (issue 92)

[Back to the README](../README.md)

Generated by `python eval/agent_cost_92.py`. Free: no model is called; the recorded tool sequences of the #61 agent runs are replayed through the tools, which are deterministic code. The #61 datasets are development data now, so these numbers can guide release 2 but cannot confirm it.

## Summary

- v3.0 and v3.1 are unchanged: 26 of 26 recorded #61 agent runs replay identically, tool result by tool result.
- An agent run cost $0.43 on average at v3.1 (at most $0.51); prompt caching is working (the recorded cost is below what uncached input alone would cost), so most of the money is output and thinking, not resent tool results.
- Tool results cost about $0.090 a run with caching, so trimming them is not worth a behavior change; not implemented.
- Implemented behind version 3.2: a $1.00 cap (twice the most expensive recorded run), no LLM judge (saves about $0.12 an arm), usage logged per turn, and `run_agent.py --model` and `--effort` for the smoke test below.
- Not decidable for free: a cheaper model or lower effort. A three-run smoke test on seed 42 (about $1) is proposed in section 7.

How the table is made: the recorded tool calls are replayed (with data_quality calls added), then the run's last findings are submitted the way a compliant agent would: code writes the text, a held upcoding finding or one that fails the checks is made inconclusive, and the submission is repeated until accepted. The defects change claims, so the replay diverges from the run after a few calls (the tool-results column) and the charts the agent asked for differ; the outcome columns therefore test the mechanics, not what an agent would have found.

What it shows: the pre-flight runs and warns on both defect profiles, per-provider flags reach the tools, and a held upcoding finding is refused until it is made inconclusive or carried by 8 charts. Under the `severe` profile every provider is flagged (six months of truncated diagnoses touch every practice), so every upcoding finding then needs chart evidence. What it cannot show: whether the model calls data_quality, reads the flags or uses flag_data_issue; no recorded run had those tools.

## 4. Where an agent run's dollars go

| Agent | Runs | Recorded cost per run (mean, range) | Turns | Tool calls | Uncached input alone would cost at least | Implied output share (if caching works) |
|---|---|---|---|---|---|---|
| v3.0 | 13 | $0.281 ($0.24 to $0.35) | 9.5 | 41.4 | $0.308 | 70% |
| v3.1 | 13 | $0.431 ($0.27 to $0.51) | 12.3 | 48.5 | $0.527 | 75% |

The lower bound counts only the system prompt, the tool schemas, the task and the tool results resent each turn, at 3 characters per token and the full input price; it leaves out the model's own earlier turns. The recorded cost is computed from the API's usage fields, so if nothing had been read from the prompt cache it could not be below that bound. **It is below it for both agents, so the cache is being read.** The usage per turn was not logged, so the split is an estimate: with cached input priced as `agent.py` prices it, most of each run's cost is output, which for this model includes its thinking.

Two things to check on the first v3.2 run, which now logs usage per turn (`turn_usage.jsonl`): the cache-read price in `agent.py` is $0.20 per million tokens, 5% of the $4.00 input price, where a 10% rate would be the usual; if the real rate is higher, recorded agent costs are slightly understated. And the cache only starts above a minimum prompt length, so the first turns may not be cached.

## 6. Caps and the judge (implemented for v3.2)

- **Dollar cap.** Recorded runs cost $0.24 to $0.51; every one stopped by submitting its findings, none by a cap. `run_agent.py` now defaults to a $1.00 cap for version 3.2 (`EVAL_MAX_USD_32`; $3 stays for 3.0 and 3.1 as run). That is about twice the most expensive run, so it would not have stopped any of them; the 80% budget notice would not have fired either. It bounds a runaway run at $1 instead of $3. The v3.2 prompt and schemas are longer (10,031 characters against 7,684 for v3.1), so watch the first runs.
- **No LLM judge for v3.2.** The agent judge cost $0.102 (v3.0) and $0.117 (v3.1) per run. `judge_agent_runs.main(..., "3.2")` now only rebuilds the view the rule judge reads (and replays office 2.1 for 3.2; it used office 2.0 for anything but 3.1, which would have broken the replay of a v3.2 run).
- **Usage per turn.** v3.2 runs write `turn_usage.jsonl` (input, output, cache read and cache write tokens per turn).

## 7. A cheaper model or lower effort (needs a paid smoke run)

Behavior cannot be replayed: a different model or effort picks different tools. By price alone, the same tokens on Sonnet 5.5 would cost 50% of Opus 5.5, about $0.22 per v3.1-like run; `effort` low would cut output and thinking, which section 4 suggests is most of the bill, by an amount only a run can show. A cheaper agent that finds fewer upcoders is a different arm, not a saving.

Proposed smoke test (not run; needs Simmy's OK): agent v3.2 on development seed 42 data 2.2, three runs: Opus 5.5 at medium (the control), Opus 5.5 at low, Sonnet 5.5 at medium (`python eval/run_agent.py <id> <code> --version 3.2 [--effort low | --model claude-sonnet-5-5]`). Estimated **about $0.45 + $0.30 + $0.25, roughly $1 in all**, under the $1 cap each. Compare upcoders found, honest doctors called, records burden, tools used and `turn_usage.jsonl`. Adopt a cheaper setting for the evaluation only if it finds as many upcoders with no new false accusations; one seed can reject a setting but cannot confirm one.
