## 2. Mutation tests

300 stored summaries that j3.2 scores 5 (sampled across the four arms), each given one known defect. Caught means the score drops by at least 1 or, for j3.2, a checklist item that passed now fails; j2.3 has no checklist.

| Defect injected | Summaries | j2.3 caught | j3.2 caught | Mean score drop j2.3 / j3.2 |
|---|---|---|---|---|
| swap a number | 300 | 42% | 97% | 0.42 / 0.39 |
| flip the leaning to upcoding on weak evidence | 238 | 100% | 100% | 1.73 / 1.11 |
| flip an upcoding leaning to high acuity | 53 | 62% | 100% | 1.09 / 2.02 |
| delete the chart evidence | 235 | 11% | 15% | 0.11 / 0.09 |
| delete the expected share | 300 | 4% | 83% | 0.04 / 0.04 |
| repeat a sentence | 300 | 26% | 20% | 0.26 / 0.20 |
| generic next steps | 300 | 100% | 100% | 1.03 / 1.03 |
| wrong fact about a cited claim | 300 | 22% | 66% | 0.22 / 0.66 |
| accusatory word | 300 | 100% | 100% | 1.00 / 1.00 |
| dollars without an estimate | 300 | 38% | 99% | 0.40 / 1.31 |
| understate a strong signal | 238 | 100% | 100% | 1.00 / 1.00 |
| certainty on weak evidence | 267 | 0% | 22% | 0.00 / 0.22 |

Two things the table shows about the score itself. A single unmatched number costs 0.5, which rounds away (as in j2.3), so j3.2 catches a swapped share mostly through the checklist (observed and expected share no longer match the evidence). And deleting the chart sentences is rarely caught because the same counts are usually stated again elsewhere (the note-check sentence gives the number of returned notes), which is partly a real limit of the check.

Overall: j2.3 caught 49% and j3.2 74% of 3131 mutated summaries. The data-caveat mutation is not in this table: no release 1 summary carries a caveat (the pre-flight is new in release 2); a unit test covers it (`tests/test_judge_rules_32.py`). A judge that catches a planted defect can still miss real ones; the human check is the test of that.

## 3. Should the writer be deterministic? Ablation on the stored runs

Workflow: every model-written summary replaced by what code alone writes (the evidence rule's leaning, else inconclusive; facts, examples and next steps by code), on the same charts.

| Arm | Summaries | Leanings changed | Upcoders called (stored / deterministic) | Honest doctors called (stored / deterministic) | j3.2 mean (stored / deterministic) | Excess stated (stored / deterministic) |
|---|---|---|---|---|---|---|
| W2.0 | 191 | 17 | 27 / 19 | 8 / 0 | 3.24 / 3.35 | 22% / 7% |
| W2.1 | 191 | 1 | 40 / 39 | 1 / 1 | 4.90 / 4.94 | 21% / 10% |

For workflow v2.1, a deterministic writer would have called 39 upcoders instead of 40 and 1 honest doctors instead of 1. For the older v2.0 prompt it would have dropped 8 true upcoding calls and 8 false ones. The judge scores are not a fair contest: the deterministic text is built by the same rules that j2.3 uses, and partly by the evidence logic j3.2 checks, so it is expected to score well.

Agent v3.1: each finding's leaning kept, its text assembled in code instead of from the agent's headline and interpretation (the structured findings #60 proposes). Outcomes are identical by construction (same leanings). On 176 findings: j3.2 mean 4.79 free text against 4.92 assembled; checklist passes leaning explained 39% / 100%, excess stated 25% / 11%, chart state 100% / 100%, next step fits leaning 97% / 97% (free / assembled).

## 5. What the release 2 evaluation uses

- **Judge:** j3.2 only (Simmy's decision); report its checklist items beside the score, since the score alone hides what a summary leaves out (for example the size of the excess).
- **Workflow writer:** not fully deterministic. On the stored v2.1 runs it would have lost 1 of 40 upcoder calls, the one where the model read notes that claim data review the claims do not show. Rules 2.2 (#91) already decide the other ambiguous cases by rule with no leaning changed, so W2.2 keeps the model for that one case.
- **Agent writer:** free-text findings as in v3.1. Assembling the text in code keeps the leanings (outcomes unchanged by construction) and scores higher on j3.2, but j3.2 shares logic with that code, the assembled text states the size of the excess less often, and telling the model its text is discarded may change what it does, which only a paid run can show.
